# i18n: Chinese Translation with Language Switcher

## Overview

Add Chinese (zh) UI translation to the portfolio site with a language switcher. English remains the default language with no URL prefix. Chinese pages live under `/zh/`. Only UI strings are translated; markdown content (blog posts, projects, publications) stays in its original language.

## URL Structure

- English (default): `/`, `/blog`, `/projects`, `/cv`, etc.
- Chinese: `/zh/`, `/zh/blog`, `/zh/projects`, `/zh/cv`, etc.
- Language switcher navigates between the two by adding/removing the `/zh` prefix

export function t(lang: Lang, key: string): string {
  return ui[lang][key] ?? ui[defaultLang][key] ?? key;
}

export function langFromUrl(url: URL): Lang {
  const [, maybeLang] = url.pathname.split("/");
  return maybeLang === "zh" ? "zh" : "en";
}

export function localizedPath(path: string, lang: Lang): string {
  return lang === "en" ? path : `/zh${path}`;
}

## Component Changes

### SidebarLayout.astro

- Add `lang` prop (default: `"en"`)
- Set `<html lang={lang}>`
- Pass `lang` to `<Sidebar />`

### Sidebar.astro

- Accept `lang` prop
- Use `t(lang, "nav.*")` for nav labels
- Use `t(lang, "sidebar.tagline")` for tagline
- Use `localizedPath()` for nav link hrefs
- Add language switcher in `.sidebar-footer`:
  ```html
  <span class="lang-switch">
    <a href={currentPathInEn} class:list={[lang === "en" && "active"]}>EN</a>
    <span class="lang-sep">/</span>
    <a href={currentPathInZh} class:list={[lang === "zh" && "active"]}>中文</a>
  </span>
  ```

### NavLink.astro

- Accept `lang` prop
- Prepend `/zh` to `href` when `lang === "zh"`

### Page files (index, blog, projects, publications, cv, contact)

- Accept and pass `lang` prop through layout
- Replace all hardcoded English UI strings with `t(lang, key)` calls
- Use `localizedPath()` for internal links (e.g., "All projects →")

### PostCard.astro, ProjectCard.astro

- Accept `lang` prop
- Use `localizedPath()` for slug links so cards link to `/zh/blog/[slug]` in Chinese mode

## Chinese Page Mirrors

Create `src/pages/zh/` with thin wrappers for each page. Each zh page imports and re-exports the same logic as its English counterpart but passes `lang="zh"`. Example for the home page:

```astro
---
// src/pages/zh/index.astro — thin wrapper
// Duplicates the data-fetching from the English home page, passes lang="zh"
import SidebarLayout from '../../layouts/SidebarLayout.astro';
import ProjectCard from '../../components/ProjectCard.astro';
import PostCard from '../../components/PostCard.astro';
import { getCollection } from 'astro:content';
import { t } from '../../i18n/ui';

const lang = 'zh';
const featuredProjects = (await getCollection('projects', ({ data }) => data.featured)).slice(0, 3);
const recentPosts = (await getCollection('blog', ({ data }) => !data.draft))
  .sort((a, b) => b.data.date.getTime() - a.data.date.getTime())
  .slice(0, 4);
---
<SidebarLayout title={t(lang, 'nav.about')} lang={lang}>
  <!-- Same markup as English home, but using t(lang, key) for all UI strings -->
</SidebarLayout>
```

The zh pages duplicate the template markup (not extracted into shared components) to keep things simple and avoid over-abstracting for just two languages.

## Language Switcher Behavior

- Displayed as `EN / 中文` in the sidebar footer, separated by a `/` divider
- Current language link is styled with accent color (not clickable or dimmed)
- Clicking the other language navigates to the equivalent path: `/blog` ↔ `/zh/blog`, `/projects/homepage` ↔ `/zh/projects/homepage`
- The switcher computes target paths by adding/stripping the `/zh` prefix from `Astro.url.pathname`
