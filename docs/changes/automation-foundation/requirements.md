# 自动开发基础设施需求

## 原始需求

要求构建大模型自动化开发流程：由我提出原始需求，你进行需求分析，生成方案文档，完成代码开发，进行测试，提出 PR，然后等待我审批后合入代码仓，推送到 GitHub。全程需要我参与的只有需求提出和代码审批。

用户随后要求“执行该方案”，并明确本次尚未配置 API / GitHub App 凭据，先完成代码和 PR。

## 范围与假设

- 本 PR 建立执行流程、规范、门禁及现有主页的回归基线，不进行主页架构重构或视觉改版。
- 中英文六模块、现有内容、项目详情与两份简历 PDF 必须保留。
- 首次配置完成后，通过所有者的 GitHub Issue / workflow_dispatch 接收需求；当前聊天也可继续作为人工交给代理的需求入口。
- 开发分支推送和建 PR 已获授权；master 合入和发布必须等待代码审批。
- 密钥、App 和仓库管理设置不包含在源代码中，也不在此次缺凭据的情况下声称已启用。

## 验收

| 编号 | 结果 | 验证 |
| --- | --- | --- |
| R1 | 需求、方案、验证文档和代理规则可复用 | AGENTS、模板及操作说明审查 |
| R2 | 可信需求自动执行最多三轮开发 / 验证 / 审查并创建 PR | 工作流 actionlint、入口与权限测试；实际模型运行待密钥配置 |
| R3 | 未审批、旧审批、失败 / 跳过检查、自审批不能自动合入 | merge-policy 单元测试和 native branch protection 复核 |
| R4 | 六模块的两种语言、已有内容和资源保留 | 类型、构建、完整性与浏览器测试 |
| R5 | 博客公式与草稿过滤仍可用 | 临时 fixture 静态构建测试 |
| R6 | 审批后部署且检查线上模块及 PDF | 部署脚本与工作流校验；实际发布待审批 |

## 不在本次范围

OpenAI 密钥创建 / 费用设置、GitHub App 注册安装、未经批准合入、已有依赖的大版本升级，以及个人联系方式事实修订。
